# 招聘问答评测问题集 · 标注规范（v2）

> 本规范用于 `dataset/data/recruitment_qa.csv` 的意图标注。v1 经 20 条试标后修订为 v2，修订记录见《标注质控流程.md》。

## 一、意图体系（4 类）

| intent | 定义 | 典型问法特征 |
| --- | --- | --- |
| 岗位查询 | 询问岗位的存在性、归属、职责、地点、招聘流程等客观信息 | 「有没有/是不是/是什么/在哪个部门」 |
| 薪资咨询 | 询问工资、奖金、补贴、发放、调薪、试用期折算等薪酬待遇 | 「多少钱/几号发/怎么算/多少比例」 |
| 技能要求 | 询问任职资格、认证、工具、协议、经验年限等能力门槛 | 「需要会什么/要什么证书/有帮助吗」 |
| 岗位推荐 | 带个人条件或倾向，请求匹配、比较或推荐岗位 | 「我能投哪个/帮我对比/适不适合我」 |

## 二、判定边界（遇到模糊情况时的裁决规则）

1. **复合问题取第一诉求**：一句话含多种意图时，按主要诉求（通常为第一个分句）归类，其余诉求记入 notes；boundary_case 标 True。
   - 例：「网络工程师岗位现在还招人吗？这个岗位和运维是一个部门吗」→ 第一诉求是招聘名额 → **岗位查询**（boundary=True）。
2. **推荐诉求优先**：只要出现「帮我选/适合我/推荐哪个」等请求，即使附带薪资或技能疑虑，一律归 **岗位推荐**；附加疑虑记 notes。
   - 例：「我同时收到两个 offer 意向，从值班强度和出差频率帮我对比」→ **岗位推荐**。
3. **问门槛 vs 问自己**：只问岗位要求（不涉及自身条件）归技能要求；把自身条件带入比较的归岗位推荐。
   - 例：「网络工程师需要什么认证」→ 技能要求；「刚考完 HCIP 没工作经验能匹配哪个岗位」→ 岗位推荐。
4. **薪资的具体化程度不影响归类**：无论是问范围、折算还是年度总收入，只要核心诉求是钱 → 薪资咨询。

## 三、难度分级

| difficulty | 标准 |
| --- | --- |
| easy | 直接问单个事实，答案在制度文档中可直接定位 |
| medium | 带限定条件（岗位+子话题、假设场景），需定位到具体条款 |
| hard | 多条件组合或需跨条款综合推理；boundary 样本默认 hard |

## 四、边界样本（boundary_case=True）判定口径

以下四类问题标为边界样本（本集共 20 条，每类意图 5 条）：

- **一题多意图**：存在性 + 部门归属、区间 + 试用期折算等复合诉求；
- **指代不明**：「这个岗位」「那个方向」缺少明确指代对象；
- **行业黑话**：如「懂监控」（Zabbix/Prometheus 要求强度不明）、「带警告的有害输出」式的模糊表述；
- **薪资区间模糊**：「8 到 13K 到手多少」等口语化、非标准的区间表述。

## 五、示例（每类 3 条，含 1 条边界）

### 岗位查询
1. 「公司现在有网络工程师的招聘名额吗」→ 岗位查询 / easy
2. 「测试工程师岗位的具体工作内容是什么」→ 岗位查询 / easy
3. 「网络工程师岗位现在还招人吗？这个岗位和运维是一个部门吗」→ 岗位查询 / **boundary**（一题多意图）

### 薪资咨询
1. 「工资每月几号发」→ 薪资咨询 / easy
2. 「绩效工资占月薪的比例是多少」→ 薪资咨询 / easy
3. 「薪资 8 到 13K 的话到手大概多少，试用期按 80% 还是更低」→ 薪资咨询 / **boundary**（区间模糊 + 复合）

### 技能要求
1. 「网络工程师需要什么认证」→ 技能要求 / easy
2. 「不会 Python 能做运维工程师吗」→ 技能要求 / medium（否定式提问）
3. 「运维岗说要懂监控，会 Zabbix 就够了还是要会 Prometheus，算加分还是必须」→ 技能要求 / **boundary**（黑话 + 要求强度不明）

### 岗位推荐
1. 「应届生可以投测试工程师吗」→ 岗位推荐 / easy
2. 「自学了 Python 和 Selenium 想找测试相关的工作能投吗」→ 岗位推荐 / medium
3. 「我是学网络的应届生，性格内向，适合投哪个岗位，会不会因为沟通被刷」→ 岗位推荐 / **boundary**（条件 + 推荐 + 自我疑虑多意图）
